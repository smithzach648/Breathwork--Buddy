# Future Environment Studio boundaries (design only)

Phase 4C.1 is an isolated local instrument. No production route, settings, database, practice timing, signal, background player or saved recipe has changed. Phase 4C.2 refinement and Phase 4C.3 integration need a later user instruction.

The narrow reusable boundary is `validateRecipe → immutable resolved Recipe → Synth`. `carrier`, `delayAt`, `gains`, `warmSteps`, `measure`, `spectrum` and `encodeWav` are typed independent operations. UI, AudioWorklet ownership and worker export are separate adapters. JSON is data only; unknown keys/versions and executable imports are rejected. Public packages/dependencies remain unchanged. Output settings do not control device volume.

Future mapping: add a versioned generated-environment variant to the actual meditation SoundRecipe only after a migration/compatibility decision. Resolve its complete recipe at Start and deep-freeze it in the parent's FrozenSound snapshot. Stable ID alone is insufficient; a custom library row could change after Start. Start Again must reuse all resolved synthesis parameters, engine version and seed. The existing monotonic practice engine remains authoritative; synthesis consumes its actual phase/window and clock origin and never writes exercise deadlines.

Continuous Warm transition: use a future adapter that shares the seeded noise source and absolute sample clock when entering meditation, then ramp delayed mix/tones from that common source. Phase 4B uses unseeded production generation; a seamless bridge needs explicit source ownership/seed and phase-continuity work, not a second masking source hidden behind a fade. Define how elapsed samples reconcile after suspension and how a timebase relates to the existing clock. Preserve the current single Master, original recorded bowl/full tail, BackgroundGain volume ownership, and one compatible media transport.

Before integration: decide which original environments the user's listening supports; choose fixed vs gliding timelines; establish default bounds and width/mix; decide lab recipe library persistence; resolve renderer source cache/memory and worker ownership; profile target phones, interruption/lock-screen behavior and a full 60-minute run. Prove shared-source/no-click transitions, frozen Start Again, late-work cancellation, one parent History, unchanged local-media records and installed offline PWA. Any production adapter must avoid double Master/trim and disclose tone/noise normalization. The lab's RMS A/B matching is not a production compressor.

Estimated scope: several implementation checkpoints for schema/validation, runtime adapter/source ownership, editor UI, audio lifecycle/mobile profiling, regression/native/PWA QA. This is not a time promise. Risks are continuous phase/source handoff, mobile worklet CPU, changing engine versions in saved recipes, correlated-delay coloration, browser suspension, output calibration and confusing exploratory names with guaranteed states. Do not ship long renders or proprietary recordings; generate in real time and export short samples only on demand.
